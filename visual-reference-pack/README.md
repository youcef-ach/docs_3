## 1. Purpose of this Directory

This directory provides an authoritative, browser-verified **Visual Reference Pack** capturing contemporary best practices in web application landing pages for 3D spatial reality capture, industrial digital twins, drone photogrammetry, and geospatial analytics.

## 2. Scope & Reference Boundaries

1. **External Visual & Product References Only**:
   * The 9 platforms documented herein (**Matterport, OpenSpace, DroneDeploy, Polycam, Bentley iTwin, Cesium, Hexagon GeoCloud, Trimble Reality Capture, and Autodesk Construction Cloud**) are external third-party market benchmarks.
   * All screenshots and observations are collected strictly as design research references.
   * No third-party logos, trademarked assets, brand fonts, or proprietary UI components are copied or claimed.

2. **MAJARA Platform Boundary Clarification**:
   * **MAJARA is an architectural and design-system reference ONLY.**
   * MAJARA establishes repository boundaries, contract-first TypeBox/Zod validation, Vanilla Extract token structures, and Tauri WebView performance constraints.
   * **MAJARA is NOT the visual identity target.** The visual identity target for the Digital Twin landing page is modern high-fidelity industrial 3D digital reality, inspired by the spatial computing leaders documented in this pack.

3. **Strict Separation of OBSERVED vs. INTERPRETED**:
   * **OBSERVED**: Concrete, verifiable DOM layout measurements, typography scales, container structures, color hex codes, and responsive behaviors directly visible in the live browser captures.
   * **INTERPRETED**: Strategic design synthesis, architectural takeaways, and practical application to the Digital Twin codebase.

## 4. Screenshot Naming Convention

All screenshots in \screenshots/\ follow a standardized machine-readable naming pattern:

\\	ext
<source>__<section>__<viewport>.png
\
* **\<source>\**: Identifies the reference platform (\matterport\, \openspace\, \dronedeploy\, \polycam\, \entley-itwin\, \cesium\, \hexagon\, \	rimble\, \utodesk\).
* **\<section>\**: Identifies the specific page section captured (\hero\, \product-showcase\, \workflow\, \cards\, \enefits\, \capabilities\, \enterprise-trust\).
* **\<viewport>\**: Identifies the tested browser viewport width:
  * **d0\**: Desktop browser window (1440 x 900).
  * **90\**: Mobile browser window (390 x 844).

### Examples:
